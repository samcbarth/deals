# deals.samcbarth.com (Deal Notes)

Amazon affiliate buying guides, deal-event explainers and a small news section ("Deal Notes Dispatch").
Plain static HTML generated by `build.py` from JSON in `data/`. Follows `C:\SamSites\NETWORK.md`.

## Run locally

```
python build.py                      # regenerate every page, feed, sitemap
python tools/check_site.py           # internal links, GTM, meta, JSON-LD, disclosure order, no em dashes/emojis
python tools/check_site.py --external   # also fetch every source link
python -m http.server 8826           # preview at http://localhost:8826
```

Preview entry `deals` (port 8826) is in `.claude/launch.json` here and in the shared `C:\.claude\launch.json`.

Never edit generated HTML (`index.html`, `guides/`, `deal-events/`, `news/`, etc.); `build.py` deletes and rewrites it.

## Adding content

| What | Where | Notes |
|---|---|---|
| Buying guide | `data/guides/<slug>.json` | Copy an existing guide. Each pick needs `sources` (a published, test-based review), `amazon.search` (or `amazon.asin`), `band` and `recipients`. Add the slug to `GUIDE_ORDER` in `build.py`. |
| Gift idea | `gift_refs` in `data/guides/gifts.json` | `"<guide-slug>/<pick-id>"`, so gifts always point at a sourced pick. |
| Deal event / explainer / legal page | `data/pages/<slug>.json` | `kind` = `event`, `explainer` or `legal`. Event dates only from Amazon's own announcements (aboutamazon.com, press.aboutamazon.com, amazon.com help pages), each in `facts` with its source. Add new events to `EVENT_ORDER`. |
| News story | `data/news/<slug>.json` | Fields: `slug, title, date_published (ISO with offset), summary, body[], tags[], image, source{label,url}, related[]`. Original write-up, primary source link required, nothing unverified. `image` is one of `news-retail`, `news-recall`, `news-tech` (add more in `IMAGES` in `build.py`). |

Then `python build.py && python tools/check_site.py` and commit.

Writing rules: no em dashes, no emojis, no hype verbs, no invented quotes/stats/testing. Question headings with a 1 to 2 sentence answer first.

## Config ids (all empty until accounts exist)

`assets/config.js`:

- `AMAZON_TAG`: Associates tracking id. `build.py` bakes it into every "Check price on Amazon" link (re-run the build), and `site.js` also applies it at runtime.
- `ADSENSE_CLIENT`: `ca-pub-...`. Empty = ad slots stay hidden and empty.
- `HUBSPOT_PORTAL` (20693956) + `HUBSPOT_FORM_ID`: contact form. Empty form id = contact page falls back to `CONTACT_EMAIL`, and if that is also empty shows a "being set up" note. **Pick one before applying to Associates/AdSense**: a working contact method is required.

`ads.txt` lives at the root domain samcbarth.com (HubSpot), not here.

## Amazon rules and the live-price upgrade path

Until the Product Advertising API (PA-API) is available, the site shows **no Amazon prices, star ratings, review counts or deal timers**. Buttons say "Check price on Amazon" and open an Amazon search (or `/dp/ASIN`) with the tag.

PA-API access opens only after the Associates account makes **3 qualifying sales within 180 days** of signing up (otherwise the account is closed and you reapply). After that:

1. Fill each pick's `amazon.asin` in the guide JSON (links switch to `/dp/ASIN`).
2. Write a small script (e.g. `tools/update_prices.py`) that calls PA-API `GetItems` for all ASINs and writes `price.live`, `price.currency`, `price.fetched_at` into each pick.
3. `build.py` already renders "Price at Amazon: ... (as of <time>)" only when both `live` and `fetched_at` are set. Amazon requires the timestamp and that prices be refreshed at least every 24 hours, so run the script + build on a daily schedule (GitHub Action) or drop prices again.
4. Star ratings remain off unless PA-API returns them and Amazon's current terms allow showing them.

## News feed (network connection)

`/news/feed.json` is JSON Feed 1.1 with `title, url, date_published, summary, image, tags` per item (plus `content_text` and `external_url` = primary source). news.samcbarth.com reads it. RSS for the whole site: `/rss.xml`.
